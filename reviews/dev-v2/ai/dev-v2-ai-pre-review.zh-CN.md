## 3. 两个确定的证据缺口

### A / dev-02：复合断言只引用了一半

预测含“GET 在连接重置后重试”和“POST 从不重试”，但唯一引文是：

> RelayGate retries GET requests after a connection reset.

这句话既没有 POST，也没有禁止 POST 重试。原始段落的另一句确实能支持 POST，但没有被输出引用，审阅者不能替模型补证据。拆分后的 g1 证据充分，g2 不充分；两者的 verdict 仍都正确。

### A / dev-07：一般规则缺少实体归属

唯一引文是：

> Every service in mode Q encrypts its stored payloads.

它只证明 Q 中的 service 会加密，不能单独证明 Juniper 在 Q。需要另外引用 passage 0 的 Juniper∈Q。标签正确、误支持率为零都不能消除这个证据缺口。

## 4. 三个短引用边界及口径建议

| 位置 | 模型实际引用 | 引文外的局部归属信息 | 已引用的实质命题 |
|---|---|---|---|
| B / dev-01 / p1 | Snapshots are retained for seven days. | 同段前句中的 ArchiveBox 及其 snapshots | 保留七天 |
| B / dev-02 / p1 | It never retries POST requests. | It 的先行词 RelayGate | 从不重试 POST |
| A、B / dev-03 / p1 | Additional workers remain queued. | TaskDock 及其活跃 worker 上限范围 | 额外 worker 排队 |

有两种合理而不同的严格度：

1. **引文独立完整**：仅看引用片段，主体、指代和范围必须充分。上述边界均暂判不充分，建议未来候选引用更长的片段。
2. **允许同段局部指代解析**：允许在已经引用的段落中解析 It、snapshots、additional 的归属；实质断言和每个独立推理前提仍必须出现在引用集合中。上述边界可通过，A/dev-02 的 POST 和 A/dev-07 的 Juniper∈Q 仍不能通过。

**我建议采用第二种作为主口径，同时报告第一种作为敏感性检查。** 原因是 citation 同时提供段落索引和引文，正常阅读会利用段落解析指代；不应把合理短引文误判为伪证据。代价是人工需要区分“解析主体”与“偷偷补入未引用的独立事实”，因此必须写成明确规则并保持各方法一致。如果选第一种，也应公平地给 B 的短引文扣分，不能看到方法表现后改变规则。

这只是本轮预审建议，尚未成为用户批准的评分口径。建议 JSON 对边界保留 `evidence_sufficient=null`，另外标记 `local_coreference_or_scope`，避免悄悄定案。

## 6. 为什么不能直接降低阈值解决 A

我用当前词法实现离线重算了相关相似度，并对 0.65、0.60、0.55 做了局部反事实运行，没有修改默认阈值或重写 v2 记录。

| 事实 | 最高单句相似度 | 0.65 当前标签 | 降阈值的结果 |
|---|---:|---|---|
| dev-03：允许五个 active worker | 0.573956 | U，错误 | 0.55 时变成 S，仍错，而且是误支持 |
| dev-04：跨重启持久化 | 0.576946 | U，错误 | 0.55 时变成 S，仍错，而且是误支持 |
| dev-08：worker 在 West | 0.616572 | U，错误 | 0.60 时变成 S，但只引用 worker 在 Maple，地区桥接仍缺 |

其他观察：dev-01 的 hourly 改写与保留七天主动/被动表达分别只有约 0.3570、0.5615；dev-02 的复合断言与 GET 句相似度约 0.8020，却未覆盖 POST；dev-07 与一般规则相似度约 0.7245，却缺少实体前提。相似度大小不能表示逻辑充分性。

显式否定规则要求去掉 not/never/no 后的 token 序列完全相同。`persists` 与 `does not persist` 不满足它，除否定词外还差 `does` 和词形，因而没有识别反转。这是实现限制的具体证据，不是模型故障。

这些局部运行是诊断，不是完整阈值选择或新的优化胜利。合理下一步是先固定证据口径、批准输出审查，再按开发证据做阈值对照和针对性实验；不能用降低阈值掩盖逻辑缺陷。
